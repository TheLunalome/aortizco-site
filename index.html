    Case study

    Five weeks of empty folders

    My media server lost its storage for five weeks and nothing told me. The data was safe the whole time. The fix took an afternoon. The lesson changed the order I build things in.

    A silent failure is the real bug. Monitoring and startup order come before features.

    1. Aug 28 and Sep 11, 2026 Two host reboots. The NAS was not up yet, so the network share failed to mount and never retried. The containers started a second later and attached to empty local folders instead.
    2. Sep 11 to Oct 16 Plex, Jellyfin and the download automation ran against empty libraries. No alert fired. About 3.3 TB of media sat untouched on the NAS.
    3. Oct 16 Found the cause and fixed it. Moved the share login out of a world-readable file into a root-only credentials file, changed the mount options so boot cannot hang, and made Docker wait up to five minutes for the share before starting containers. Restarted 11 containers and checked each one.
    4. Oct 17 to 18 Added 15 uptime monitors with phone alerts. Started moving the media onto local ZFS storage so the NAS stops being a boot dependency.
