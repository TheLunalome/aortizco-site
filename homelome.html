Why this shape?

Game servers should not have to compete with media automation. A public connector should not have lateral access to the LAN. A backup target should not rely on the same failure domain as the data it protects. Separation is the design, not the aesthetic.

03 · guardrails

Useful access needs receipts.

The MCP project exists to make the lab inspectable from an assistant without giving an assistant—or a leaked hostname—more power than it needs.

  1. 1
    Identity at the edgeCloudflare Access verifies the person before the portal sees a request.
  2. 2
    Outbound-only transportThe tunnel connects outward from the lab. Home services do not publish raw management ports to the internet.
  3. 3
    Service-specific authenticationEach upstream service has its own boundary, so the portal is not a skeleton key.
  4. 4
    Read first, write later—if everThe current MCP connection is used for inspection and diagnosis. Change authority stays deliberately narrow.
  5. 5
    Keep a trailTool activity, backups, and monitoring are designed to leave evidence for later troubleshooting.

04 · notes

What this lab has taught me so far.

The best documentation is honest about what is verified, what is changing, and what still needs attention.

  • Monitoring beats vibes.A service that looks fine on a dashboard may still be broken. The lab treats alerts and actual checks as evidence, not decoration.
  • Storage is a product decision.Media capacity, backups, replication, and restore testing each have different jobs. “It has disk space” is not a backup plan.
  • Public docs have boundaries.This page shares architecture and reasoning; it intentionally excludes addresses, tokens, serial numbers, and internal configuration.
  • Every outage gets a note.The goal is less blame, more signal: what failed, what the system said, and what changed after the fix.
Known follow-up: Uptime Kuma MCP connection

The MCP portal currently lists Uptime Kuma as enabled, but a live tool request times out during upstream authentication and later returned a 502. This is being treated as a portal-to-service connectivity issue, not proof that the monitoring service itself is offline.

Known follow-up: resource headroom

One active Docker VM is currently using most of its assigned memory. It is a cue to inspect workload limits and trends before adding more services—not a reason to panic-rebuild a working environment.
